# План внедрения тестового AI-эндпоинта для Orbit

## 1. Цель и контекст
- Реализовать потоковый AI-эндпоинт для Orbit, вдохновляясь существующим `@avrora/app/(chat)/api/chat/route.ts`.
- Ограничить реализацию тестовым режимом (доступен в dev-окружении или по флагу), чтобы не нарушить текущую логику Sfera/Orbit.
- Подготовить архитектуру, позволяющую в дальнейшем перейти к полноценной интеграции в Sfera/Orbit.

## 2. Структура проекта и новые файлы
1. **API-маршрут**: `app/(orbit)/api/orbit/[id]/ai/route.ts`
   - Тестовая точка входа, возвращающая SSE-поток.
2. **Схемы и типы**: `app/(orbit)/api/orbit/[id]/ai/schema.ts`
   - Zod-схемы для валидации тела запроса и структур ответа.
3. **Утилиты**: `lib/orbit/ai-utils.ts`
   - Преобразование сообщений Orbit в формат UI messages, генерация UUID, подготовка подсказок.
4. **DB-слой/репозитории** (при необходимости)
   - Либо переиспользуем существующие методы из `lib/db`, либо добавляем обёртки для работы с Orbit/Sfera.
5. **Документация** (текущий файл `ORBIT_API.md`).

## 3. Основные шаги реализации
### 3.1. Анализ текущего решения
- Изучить `@avrora/app/(chat)/api/chat/route.ts` @avrora/app/(chat)/api/chat/route.ts#118-905: 
  - Валидация тела запроса (`postRequestBodySchema`).
  - Загрузка и очистка истории (`getMessagesByChatId` + очистка незавершённых tool-calls).
  - Подготовка `uiMessages` и вызов `streamText`.
  - Работа с `createUIMessageStream`, сохранение usage, аналитика.

### 3.2. Подготовка схемы запроса
- Создать `OrbitAIRequestSchema` (аналог `postRequestBodySchema`).
- Поля: `id`, `message`, `selectedChatModel`, `selectedVisibilityType`, опциональные аттачи.
- Соответствующие типы для typescript (`OrbitAIRequest`).

### 3.3. Проверка доступа и контекста
- Получить сессию через `auth()`; вернуть 401 при отсутствии пользователя.
- Проверить, что пользователь состоит в целевой Orbit/Sfera (аналог текущей проверки в `app/api/sfera/[id]/messages/route.ts` @avrora-area/app/api/sfera/[id]/messages/route.ts#24-37).
- Загрузить историю сообщений (например, последние 50 записей) из `sferaMessage`.
- Преобразовать историю в формат UI messages для AI SDK (текстовые части, вложения).

### 3.4. Сохранение пользовательского сообщения
- До вызова модели сохранить новое сообщение пользователя в `sferaMessage`, как в текущем маршруте @avrora-area/app/api/sfera/[id]/messages/route.ts#76-91.
- Добавить отметку о том, что сообщение отправлено через тестовый AI-эндпоинт (флаг в метаданных/частях, если нужно).

### 3.5. Подготовка промпта и подсказок
- Использовать `geolocation(request)` для формирования `requestHints` (см. @avrora/app/(chat)/api/chat/route.ts#576-583).
- Построить system prompt через `buildSystemPrompt` или аналогичную функцию (изучить `@avrora/app/(chat)/api/chat/route.ts#624-632` и `@/lib/ai/prompts`).
- Добавить специфические инструкции для Orbit (краткое описание Sfera/Orbit, роли участников).

### 3.6. Настройка потокового ответа
- Создать `createUIMessageStream`, передав:
  - `execute`: вызов `streamText` с `myProvider.languageModel(selectedChatModel)`.
  - `messages`: `convertToModelMessages(uiMessages)`.
  - `tools`: старт с минимального набора (`getWeather`, `createDocument`, `updateDocument`, `requestSuggestions`), возможность расширять.
  - `stopWhen`: например, `stepCountIs(8)`.
  - `onChunk`: логирование задержек (опционально).
- Обработать `result.toUIMessageStream({ sendStart: false, ... })`, чтобы продолжить SSE.

### 3.7. Обработка завершения и ошибок
- В `onFinish`:
  - Сохранить ответ ассистента в `sferaMessage` (role = "assistant", userId = null).
  - Сохранить usage/аналитику (по аналогии с `saveMessageAnalytics` @avrora/app/(chat)/api/chat/route.ts#872-904).
- В `onError`: 
  - Возвращать понятное сообщение, логировать детали.
  - При необходимости отправлять fallback-текст пользователю.

### 3.8. Возврат ответа клиенту
- Итоговый ответ: `Response(stream.pipeThrough(new JsonToSseTransformStream()))`.
- Для тестового режима можно добавить альтернативу: если клиент не поддерживает SSE, возвращать JSON с пометкой о недоступности (опционально).

## 4. Интеграция на фронтенде (Orbit)
1. **Настроить вызов API**
   - В `OrbitInput` добавить отправку сообщений на `/app/(orbit)/api/orbit/[id]/ai` (для теста по флагу).
   - Использовать SSE-клиент (например, `useChat` из `ai/react`) либо собственный обработчик `EventSource`.
2. **UI-индикаторы**
   - Показать «Avrora думает» при открытом стриме (аналоги уже есть в `OrbitChat`).
   - Обновлять историю сообщений по завершении стрима.
3. **Обработка ошибок**
   - Если API вернул ошибку, отображать toast/баннер.

## 5. Тестирование
1. **Unit/Integration**
   - Проверить валидацию схемы `OrbitAIRequestSchema`.
   - Смоделировать успешный поток (mock `streamText`).
   - Тест проверки доступа (участник/не участник).
2. **Manual QA**
   - Отправка сообщений с упоминанием/без упоминаний.
   - Поведение при пустом контенте/только вложениях.
   - Проверка сохранения истории и асинхронного ответа.
3. **Observability**
   - Логи по началу/завершению стрима.
