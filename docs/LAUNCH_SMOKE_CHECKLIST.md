# Launch Smoke Checklist — Orbital

Воспроизводимый ручной прогон базовых функций перед запуском. Каждый шаг —
пройдено / не пройдено + заметка. Любое падение заводится отдельной задачей.

Прогонять на **прод-подобном окружении** (не dev): реальные `POSTGRES_URL`,
`REDIS_URL`, `OLLAMA_API_KEY`, `POSTMARK_*`, `AUTH_SECRET`, `NEXT_PUBLIC_WS_URL`.
См. `.env.example` — блок «обязательные для прода».

---

## 0. Предпосылки (до прогона)

- [ ] `.env.local` (или env прод-хоста) заполнен по `.env.example`; ни одной пустой обязательной переменной.
- [ ] `GET /api/health` → `200` и все компоненты `ok` (db, redis, ai). Если `ai: false` — не задан `OLLAMA_API_KEY`, AI-шаги (6) провалятся ожидаемо.
- [ ] Приложение собрано (`pnpm build`) и запущено (`pnpm start`); WS-сервер поднят отдельно (`pnpm dev:ws` / прод-процесс).
- [ ] Миграции применены на целевой БД (`pnpm db:migrate`), `pnpm db:check` без предупреждений.

---

## 1. Регистрация и вход по magic-link

- [ ] Открыть `/login` анонимно — форма email рендерится.
- [ ] Ввести реальный email → «Создать Magic Link». В **проде** приходит письмо (Postmark); в dev код виден в консоли/на экране.
- [ ] Ввести 8-значный код → вход происходит, редирект на `/`.
- [ ] Повторить запрос кода >3 раз за 15 мин → срабатывает rate-limit (сообщение о превышении).
- [ ] Код одноразовый: повторный ввод того же кода отклоняется.
- [ ] CSRF: POST на action с чужого origin отклоняется («недопустимый источник»). *(проверяется curl'ом с поддельным Origin)*

## 2. Онбординг

- [ ] После первого входа отрабатывает `onboarding/start`, создаётся первая ячейка.
- [ ] Онбординг-агент отвечает (если AI настроен).

## 3. Живая карта (`/`)

- [ ] Карта рендерится (desktop: `OrbitNetworkTimeline`, mobile: `OrbitMobileCards`).
- [ ] Ячейка показывается с состоянием: `живёт` / `созревает` / `тихо`.
- [ ] Пустое состояние (нет ячеек) ведёт к `Создать...`, без выдуманных данных.

## 4. Создание ячейки

- [ ] CTA `Создать...` → `POST /api/sfera` → новая ячейка появляется на карте.
- [ ] Название/описание сохраняются, ячейка открывается.

## 5. Сообщения

- [ ] Открыть ячейку, отправить сообщение → сохраняется (`SferaMessage`), видно в ленте.
- [ ] Перезагрузка страницы — сообщение на месте (персистентность).

## 6. AI-ответ (Avrora)

> Требует `OLLAMA_API_KEY`. Без него ожидается **явный 503** «Avrora сейчас недоступна», а не белый экран или ошибка в тексте сообщения.

- [ ] Упомянуть `@Avrora` в сообщении → приходит стриминговый ответ (`sfera/[id]/chat`).
- [ ] Ответ дописывается инкрементально (стриминг работает).
- [ ] При снятом AI-ключе — понятное сообщение о недоступности, приложение не падает.
- [ ] Rate-limit Avrora: серия быстрых обращений → сообщение о лимите, не краш.

## 7. Форк / продолжение

- [ ] Форк сообщения → создаётся связанная ячейка (`SferaForkedSfera`).
- [ ] В UI связь отображается как `Продолжение:` (не «Forked from»).

## 8. Профиль

- [ ] `/u/[handle]` открывается (гравитационное поле).
- [ ] Владелец видит редактор профиля; сохранение (`PATCH /api/user/profile`) работает.
- [ ] Занятый позывной отклоняется (409).
- [ ] Чужой профиль — только чтение, без кнопок редактирования.

## 9. Авторизация и защита маршрутов

- [ ] Разлогин → защищённые страницы редиректят на `/login`.
- [ ] Прямой заход анонима на ячейку/профиль-редактор — отклоняется.
- [ ] Не-участник не может писать/читать приватную чужую ячейку (403).

## 10. Realtime (WebSocket)

> Требует поднятого WS-сервера и `NEXT_PUBLIC_WS_URL`.

- [ ] Соединение без валидного токена/cookie — отклоняется (`1008 Unauthorized`).
- [ ] Не-участник ячейки — отклоняется (`1008 Forbidden`).
- [ ] Валидная сессия + членство — соединение открывается, приходит `connected`.
- [ ] Во второй вкладке новое сообщение появляется без перезагрузки.

- Дата / окружение / версия (git sha): __________
- Пройдено: __ / 10 блоков
- Проваленные шаги → номера заведённых задач: __________

**Definition of Done:** все 10 блоков зелёные на прод-подобном окружении.
